# Контекст разработки

Обновлено: 2026-09-20

## Цель MVP

«Карманный бухгалтер» — веб-приложение для анализа текстовой PDF-выписки одного банка. Пользователь загружает выписку, приложение извлекает операции, распределяет расходы по категориям и показывает графики и AI-наблюдения.

Главный сценарий: **PDF → извлечение текста → OpenAI → структурированные операции → серверная агрегация → дашборд**.

## Статус

- Локальный интерфейс доступен на `http://localhost:5173`.
- API доступен на `http://localhost:3000`; health-check: `GET /api/health`.
- Production-сборка и unit-тесты проходят.
- Docker-конфигурация подготовлена, но локально Docker ещё не установлен и не проверен.
- OpenAI-ключ хранится только в локальном `.env`, никогда не добавляется в Git.

## Архитектура

- `src/client/` — React + Vite: экран загрузки и дашборд с Recharts.
- `src/server/index.ts` — Express API и загрузка PDF в памяти.
- `src/server/analyzer.ts` — OpenAI Responses API, Structured Outputs и валидация Zod.
- `src/server/summary.ts` — независимая агрегация расходов; AI не рассчитывает итоговые суммы.
- `src/server/bank-template.ts` — строгий профиль выписки Kaspi Gold. Он проверяет подпись банка, заголовок с любым периодом, таблицу операций и формат хотя бы одной операции до вызова OpenAI.

## API-контракт

### `POST /api/analyze-statement`

`multipart/form-data`, поле файла: `statement`.

Успех возвращает:

```json
{
  "period": { "from": "2026-09-01", "to": "2026-09-30" },
  "transactions": [{ "date": "2026-09-01", "merchant": "Магазин", "amount": 1200, "type": "expense", "category": "Продукты" }],
  "summary": { "totalExpenses": 1200, "transactionCount": 1, "topCategory": "Продукты", "categories": [{ "name": "Продукты", "value": 1200 }] },
  "insights": ["Продукты — крупнейшая статья расходов."]
}
```

Допустимые категории: `Продукты`, `Кафе`, `Транспорт`, `Подписки`, `Здоровье`, `Развлечения`, `Покупки`, `Переводы`, `Другое`.

## Локальный запуск

```powershell
npm.cmd install
npm.cmd run dev
```

В `.env` нужны `OPENAI_API_KEY`, `OPENAI_MODEL`, `PORT`; файл игнорируется Git. Для Docker предназначена команда `docker compose up --build`.

## Ближайшие действия

1. Прогнать обезличенный образец с API-ключом, проверить категории и AI-инсайты; при необходимости скорректировать prompt.
2. Положить обезличенный demo-PDF в `assets/` и обновить README.
3. Проверить Docker на машине с Docker Desktop перед сдачей.

## Правила работы

- Не коммитить `.env`, реальные выписки, API-ключи и персональные финансовые данные.
- Работать в feature-ветках и вносить изменения через маленькие PR.
- После изменения поведения обновлять этот документ, README и релевантные тесты.
- Перед интеграцией запускать `npm.cmd test` и `npm.cmd run build`.
