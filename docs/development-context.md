# Контекст разработки

Обновлено: 2026-09-20

## Цель MVP

«Карманный бухгалтер» — веб-приложение для анализа текстовой PDF-выписки одного банка. Пользователь загружает выписку, приложение извлекает операции, распределяет расходы по категориям и показывает графики и AI-наблюдения.

Главный сценарий: **PDF → извлечение текста → строгий парсинг операций → AI-категоризация → серверная агрегация → дашборд**.

## Статус

- При запуске `npm.cmd run dev` интерфейс доступен на `http://localhost:5173`.
- При запуске `npm.cmd run dev` API доступен на `http://localhost:3000`; health-check: `GET /api/health`.
- Production-сборка и unit-тесты проходят.
- Docker-конфигурация подготовлена, но локально Docker ещё не установлен и не проверен.
- OpenAI-ключ хранится только в локальном `.env`, никогда не добавляется в Git.

## Архитектура

- `src/client/` — React + Vite: экран загрузки, интерактивный статус анализа и дашборд с Recharts.
- `src/client/components/ui/progress.tsx` — компонент shadcn/ui для полосы прогресса.
- `src/server/index.ts` — Express API, загрузка PDF в памяти и подключение кэша анализа.
- `src/server/analysis-cache.ts` — process-local кэш успешных анализов: ключ — SHA-256 PDF, TTL — 7 дней, лимит — 100 результатов; запись на диск отсутствует, кэш очищается при рестарте API.
- `src/server/analyzer.ts` — OpenAI Responses API для категоризации уже разобранных расходов и инсайтов, Structured Outputs и валидация Zod.
- `src/server/summary.ts` — независимая агрегация расходов; AI не рассчитывает итоговые суммы.
- `src/server/bank-template.ts` — строгий профиль выписки Kaspi Gold. Он проверяет подпись банка, заголовок с любым периодом, таблицу операций и формат строк, затем детерминированно извлекает операции до вызова OpenAI.

## API-контракт

### `POST /api/analyze-statement`

`multipart/form-data`, поле файла: `statement`.

Ответ содержит заголовок `X-Analysis-Cache`: `MISS`, когда анализ выполнен впервые, либо `HIT`, когда для идентичного файла использован серверный кэш.

Успех возвращает:

```json
{
  "period": { "from": "2026-09-01", "to": "2026-09-30" },
  "transactions": [{ "date": "2026-09-01", "merchant": "Магазин", "amount": 1200, "type": "expense", "category": "Продукты" }],
  "summary": { "totalExpenses": 1200, "transactionCount": 1, "topCategory": "Продукты", "categories": [{ "name": "Продукты", "value": 1200 }] },
  "insights": ["Продукты — крупнейшая статья расходов."]
}
```

Допустимые категории: `Продукты`, `Кафе`, `Транспорт`, `Подписки`, `Здоровье`, `Развлечения`, `Покупки`, `Переводы`, `Другое`.

## Локальный запуск

```powershell
npm.cmd install
npm.cmd run dev
```

В `.env` нужны `OPENAI_API_KEY`, `OPENAI_MODEL`, `PORT`; файл игнорируется Git. Для Docker предназначена команда `docker compose up --build`.

Vite запускается на `http://localhost:5173`, API — на `http://localhost:3000`. Сервисы не должны оставаться запущенными после завершения локальной проверки.

## Состояние загрузки выписки

После отправки PDF кнопка блокируется, а под полем файла отображается доступный (`role="status"`, `aria-live="polite"`) блок обработки. Он показывает прошедшее время и последовательные сообщения: чтение файла, извлечение операций, анализ категорий и подготовка наблюдений.

Сервер не выдаёт потоковые этапы или процент выполнения, поэтому полоса прогресса является только визуальным сигналом активности: она плавно доходит максимум до 94% и не должна трактоваться как точная оценка оставшегося времени. Экран результата открывается исключительно после успешного API-ответа; при ошибке индикатор исчезает и выводится сообщение об ошибке.

## Сохранение результата в браузере

После успешного анализа клиент сохраняет последний ответ API в `localStorage` под ключом `pocket-accountant:last-analysis` и читает его при инициализации приложения. Это восстанавливает дашборд после перезагрузки страницы без нового HTTP-запроса. Кнопка «Новая выписка» удаляет эту запись. Хранилище относится к конкретному origin браузера и профилю; оно не является заменой серверному кэшу и не участвует в повторной отправке PDF.

## Ближайшие действия

1. Прогнать обезличенный образец с API-ключом, проверить категории и AI-инсайты; при необходимости скорректировать prompt.
2. Положить обезличенный demo-PDF в `assets/` и обновить README.
3. Проверить Docker на машине с Docker Desktop перед сдачей.

## Правила работы

- Не коммитить `.env`, реальные выписки, API-ключи и персональные финансовые данные.
- Работать в feature-ветках и вносить изменения через маленькие PR.
- После изменения поведения, API, конфигурации, архитектуры или пользовательского сценария в том же изменении обновлять этот документ, README и релевантные тесты. Не откладывать документацию на последующую задачу.
- Перед интеграцией запускать `npm.cmd test` и `npm.cmd run build`.
