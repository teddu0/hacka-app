# Карманный бухгалтер

AI-сервис для анализа текстовой PDF-выписки одного банка. Он извлекает операции, распределяет расходы по категориям и показывает визуальную сводку с персональными наблюдениями. Проект сделан как MVP для AI-хакатона: у него один проверяемый сквозной сценарий, а выписки не сохраняются.

Интерфейс поддерживает светлую и тёмную тему; переключатель находится в верхней части экрана, а выбор сохраняется в браузере.

## Что реализовано

1. Пользователь загружает цифровую PDF-выписку до 8 МБ.
2. Сервер извлекает текст и проверяет, похож ли документ на выписку банка.
3. OpenAI API возвращает строго структурированный набор операций и AI-инсайты.
4. Во время анализа интерфейс показывает текущий этап, прошедшее время и плавный индикатор прогресса.
5. Сервер независимо агрегирует расходы; интерфейс показывает KPI, круговую диаграмму, инсайты и все операции.

Поддерживаются текстовые PDF. Сканированные документы, фото, другие банки, история операций, авторизация и финансовые рекомендации не входят в MVP.

## Архитектура

```text
React/Vite → POST /api/analyze-statement → SHA-256 lookup in server cache
                                           → PDF text extraction (on cache miss)
                                           → bank-template validation
                                           → OpenAI Structured Outputs (on cache miss)
                                           → aggregation → dashboard

Во время ожидания ответа UI локально отсчитывает время и меняет понятные статусы обработки. Индикатор намеренно не отображает точный серверный процент: API не передаёт этапы выполнения. Он плавно останавливается на 94% и завершается только после фактического ответа API.
```

`src/server/bank-template.ts` — изолированный профиль выписки банка. После получения образца PDF здесь фиксируются сигнатуры, заголовки и форматы строк, не меняя API или интерфейс. `src/server/summary.ts` рассчитывает итоговые значения независимо от ответа модели.

## Технологии и данные

- TypeScript, React, Vite, Express, Recharts;
- `pdf-parse` для текста PDF;
- OpenAI Responses API и Structured Outputs для типизированного результата;
- `zod` для проверки AI-ответа;
- файл живёт только в памяти запроса: выписки и извлечённый текст не пишутся в БД или на диск.
- готовый результат одинаковой PDF-выписки временно хранится только в оперативной памяти сервера, а последний отчёт — в `localStorage` браузера; подробности и ограничения описаны ниже.

## Кэширование и сохранение отчёта

### Серверный кэш анализа

Для каждой загружаемой PDF сервер вычисляет SHA-256 от исходных байтов файла. Если идентичная выписка уже была успешно проанализирована, готовый результат возвращается из process-local кэша и OpenAI не вызывается повторно. Это также исключает повторные извлечение текста PDF и валидацию шаблона.

- срок жизни записи — 7 дней;
- в памяти хранится не более 100 результатов;
- параллельные загрузки одного и того же файла используют одну выполняющуюся операцию;
- кэш находится только в памяти процесса: после перезапуска API он очищается;
- PDF, извлечённый текст и результаты не записываются сервером на диск или в БД.

Для диагностики ответ `POST /api/analyze-statement` содержит заголовок `X-Analysis-Cache`: `MISS` для нового анализа и `HIT` для кэшированного ответа.

### Восстановление отчёта в браузере

После успешного анализа весь готовый отчёт сохраняется в `localStorage` текущего origin под ключом `pocket-accountant:last-analysis`. Благодаря этому перезагрузка страницы не сбрасывает дашборд и не создаёт новый запрос к API.

- это хранилище принадлежит конкретному браузерному профилю и origin: другой домен, порт, профиль или окно инкогнито его не видят;
- серверный перезапуск не очищает `localStorage`;
- кнопка «Новая выписка» удаляет сохранённый отчёт;
- хранится только один, последний отчёт; следующий успешный анализ заменяет его;
- при повторной загрузке файла через форму `localStorage` не используется как серверный кэш: после рестарта API такая загрузка снова вызовет OpenAI;
- отчёт содержит финансовые данные, поэтому пользователь должен очищать данные сайта на общем устройстве.

## Быстрый запуск

Нужны Docker и действующий API-ключ OpenAI.

```bash
cp .env.example .env
# Добавьте OPENAI_API_KEY в .env
docker compose up --build
```

Откройте `http://localhost:3000`. В Windows можно создать `.env` вручную по примеру `.env.example`.

Для локальной разработки с Node.js 24:

```bash
npm.cmd install
npm.cmd run dev
```

## Проверка основного сценария

1. Откройте приложение и выберите экспортированную из банковского приложения текстовую PDF-выписку.
2. Нажмите «Проанализировать».
3. Во время обработки убедитесь, что появляются статус, таймер и индикатор прогресса; кнопка отправки недоступна до получения ответа.
4. Убедитесь, что после ответа показаны период, сумма расходов, число операций, главная категория, диаграмма, таблица и AI-наблюдения.
5. Загрузите файл не в PDF-формате или скан без текста: приложение должно показать понятную ошибку.

Перед демонстрацией положите обезличенный образец выписки в `assets/` и уточните под него правила в `bank-template.ts`. Не добавляйте реальные персональные финансовые данные в репозиторий.

## Конфигурация

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Да | Серверный ключ OpenAI; не передаётся браузеру |
| `OPENAI_MODEL` | Нет | Модель для анализа, по умолчанию `gpt-5.5` |
| `PORT` | Нет | Порт приложения, по умолчанию `3000` |
| `BANK_TEMPLATE_NAME` | Нет | Название профиля банка в AI-инструкции |

## Надёжность и ограничения

API ограничивает размер загрузки, принимает только PDF, отклоняет пустой текст и невалидный шаблон, валидирует JSON модели и сообщает ошибки без раскрытия данных. Сервис не является финансовой рекомендацией. Категоризация может потребовать уточнения после появления реального образца выписки.
